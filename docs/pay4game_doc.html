Документация API

Авторизация

Для авторизации необходимо в заголовке Authorization передавать токен: Authorization: Bearer

Токен авторизации можно получить на странице Настройки.

Создание платежа

1. Отправьте запрос на проведение платежа с помощью метода payment/create. В ответ на запрос в параметре url передается ссылка на страницу оплаты.

Полученную ссылку в iframe открывать нельзя, только в новой или текущей вкладке

2. Дождитесь вебхука inform. В параметре qr.content передается диплинк на оплату, который либо можно показать плательщику в виде QR-кода, либо отправить по нему плательщика в приложение эмитента. URL для возврата пользователя из приложения эмитента необходимо прописать на странице Настройки.

  • Вебхук inform отправляется только для способа оплаты sbp и переданного параметра sbp_type=qr. Для card и sberpay в ответ на запрос создания платежа приходит url на страницу оплаты. Для ответа qr обратитесь к администратору.

3. Дождитесь вебхука status с результатом проведения платежа. Статус success сообщает вам, что платеж успешно проведен.

  • Обязательно проверяйте подпись запроса.
  • Обязательно проверяйте параметр hold. Подробнее в разделе Вебхуки.

Для отображения виджета на своем сайте при способе оплаты card обратитесь к администратору. После включения данной опции в ответ будет приходить token, с помощью которого можно отобразить виджет согласно инструкции.

POST payment/create

Параметры запроса
Тег Тип Описание
method string Способ оплаты (sbp, card, sberpay, tpay, cardkz, carduz, uzum). По умолчанию sbp
sbp_type string Тип ответа sbp (qr или url). По умолчанию url (для ответа qr обратитесь к администратору)
invoice_id string Идентификатор заказа
amount decimal Сумма заказа
email string E-mail клиента
client_ip string IP адрес клиента
return_url string URL для возврата пользователя
steam_account string Логин Steam
steam_amount decimal Сумма пополнения баланса Steam (мин.: 20 руб., макс.: 50000 руб.)
risk integer Товар высокого риска (0 - нет, 1 - да)

Если переданы параметры steam_account и steam_amount, то в ответе придет дополнительный параметр agent_transaction_id. После успешной оплаты будет выполнено пополнение баланса Steam и отправлен вебхук status_steam

Подпись запроса

Для формирование подписи необходимо использовать следующие данные: "Идентификатор заказа:Сумма заказа:E-mail клиента" (разделены символом ":").

Вычисляется HMAC по алгоритму SHA256. Секретный ключ можно получить на странице Настройки.

Подпись необходимо передать в заголовке X-REQUEST-SIGNATURE

Если у вас несколько проектов, то обязательно необходимо передавать ID проекта в заголовке X-REQUEST-PROJECT

Создание выплаты

1. Отправьте запрос на проведение выплаты с помощью метода payout/create.

2. Дождитесь вебхука status_payoff с результатом проведения выплаты. Статус success сообщает вам, что выплаты успешно проведена.

  • Обязательно проверяйте подпись запроса.

Вебхуки

Как получать вебхуки

1. В вашей системе создайте адрес, на который хотите получать вебхуки.

2. Пропишите его на странице Настройки.

Что отправлять в ответ

В ответ на любой вебхук необходимо отправить HTTP-код 200.

Если в ответ pay4game получит код 4** или 5**, то будет отправлять запрос через увеличивающийся промежуток времени, пока не получит ответ.

Проверка подписи

Для формирование подписи необходимо использовать данные из тела запроса. Вычисляется HMAC по алгоритму SHA256. Секретный ключ можно получить на странице Настройки.

Полученную подпись необходимо сравнить с переданной в заголовке X-REQUEST-SIGNATURE

Перед выдачей заказа обязательно проверяйте параметр hold:

  • если hold = 0 - платеж прошел успешно и заказ можно выдавать.
  • если hold = 1 - платеж прошел успешно, но заблокирован сервисом для проверки Администратором. После проверки будет повторно отправлен вебхук.
